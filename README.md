# WTK-Games · Pixel Kingdoms

เกมการ์ดสามก๊กบทบาทลับ บนโต๊ะศึก HD-2D เล่นออนไลน์หรือฝึกกับบอท

[เริ่มเล่น](#quick-start) · [กติกา](#gameplay) · [พัฒนา](#development) · [เอกสาร](#documentation)

WTK-Games เป็นเกมบนเว็บสำหรับผู้เล่น 4–10 คน ผสมการอ่านใจ การวางแผน และสกิลขุนพล โดย Colyseus Server เป็นผู้ตัดสินกติกาและส่งข้อมูลที่ผู้เล่นแต่ละคนมีสิทธิ์เห็น Client ปัจจุบันใช้ TypeScript, Three.js และ GSAP พร้อม UI ภาษาไทยที่รองรับเมาส์และการแตะ ทั้งจอแนวตั้งและแนวนอน

## จุดเด่น

- โต๊ะไม้ศึก ขอบสำริด แผนที่ผ้า และลานวังแสงโคมตัดแสงจันทร์
- ตัวละครยืนบนฐาน กล้องนิ่ง และเอฟเฟกต์การ์ดกับสกิลขุนพล
- มือไพ่แบบพัด ไพ่กลางโต๊ะขนาดกระชับ และแตะดูรายละเอียดใบใหญ่ได้
- เสียงเอฟเฟกต์พร้อมปรับระดับ/ปิดเสียง และโหมดลดเอฟเฟกต์
- ห้องบอทและออนไลน์ เลือกกติกา Standard หรือ Experimental
- วาดฉากเมื่อข้อมูลเปลี่ยนหรือมีแอนิเมชัน พักเมื่อฉากนิ่ง/ซ่อนแท็บ และลดรายละเอียดอัตโนมัติ

## ติดตั้งและเริ่มเล่น

ต้องมี Git, npm และ **Node.js 22.12 ขึ้นไป** หรือ Node.js 20.19 ขึ้นไปในสาย 20 ตามข้อกำหนดของ Vite 8 ใช้เบราว์เซอร์ที่รองรับ WebGL สำหรับฉาก 3D

```bash
git clone https://github.com/Itsmnatom/WTK-Games.git
cd WTK-Games
npm ci
```

คัดลอกไฟล์ตั้งค่าบน PowerShell:

```powershell
Copy-Item .env.example .env
```

หรือบน macOS/Linux:

```bash
cp .env.example .env
```

แก้ค่าใน `.env` โดยคง `PORT=3001` สำหรับการพัฒนาในเครื่อง แล้วรันจากโฟลเดอร์โปรเจกต์:

```bash
npm run build
npm start
```

เปิด **[http://localhost:3001/lobby](http://localhost:3001/lobby)** ตั้งชื่อ เลือกโหมดบอทหรือออนไลน์ และสร้างห้อง ส่งรหัสห้องให้เพื่อนเพื่อเข้าร่วม

`npm start` รันไฟล์ที่คอมไพล์แล้ว จึงต้อง build หลังแก้โค้ด หากไม่ตั้ง `PORT` โค้ด Server จะใช้ **3002**; ตัวอย่างนี้ใช้ `.env.example` เพื่อตั้งเป็น 3001 ให้ตรงกับ Vite

## กติกาและโหมดปัจจุบัน

| รายการ | พฤติกรรม |
| --- | --- |
| ผู้เล่น | 4–10 คน ค่าเริ่มต้น 6 คน |
| บทบาท | เจ้าเมือง ภักดี กบฏ และทรยศ โดยซ่อนข้อมูลตามบทบาท |
| สำรับ | 176 ใบ ครบ 41 ชนิด |
| เวลาเล่นไพ่ | ไม่จำกัดเวลา |
| ตอบโต้ทั่วไป | 20 วินาที หมดเวลาถือว่าผ่าน ไม่ใช้ไพ่แทนผู้เล่น |
| เลือกขุนพล | 90 วินาที หมดเวลาเลือกตัวแรกในชุดที่เสนอ |
| การเชื่อมต่อหลุด | กลับเข้าได้ภายใน 45 วินาที หากไม่กลับถือว่าตายและเกมดำเนินต่อ |

**แผนกลยุทธ์เป็นกติกาหลักของทุกห้อง** ใช้ขุนพลครบ 19 คน ทั้งเล่นกับบอทและออนไลน์ ไม่มีโหมดมาตรฐานแยก ค่าของแผนและขุนพลยังต้องประเมินสมดุลจากแมตช์จริง

เริ่มเล่นผ่านปุ่ม **เล่นโหมดแผนกลยุทธ์** หรือเปิด [localhost:3001/lobby](http://localhost:3001/lobby) แล้วสร้างห้อง ทุกคนเลือกหนึ่งแผนหลังเลือกขุนพล เลือกซ้ำกันได้ และเปิดเผยพร้อมกันเมื่อขั้นตอนเลือกสิ้นสุด แต่ละแผนใช้ได้หนึ่งครั้งต่อแมตช์:

| แผน | ช่วงใช้งาน | ต้นทุนและผล |
| --- | --- | --- |
| จัดทัพ | ช่วงเล่นไพ่ | ทิ้งไพ่บนมือ 1 ใบ จั่ว 2 ใบ |
| เร่งบุก | ช่วงเล่นไพ่ | ทิ้งไพ่บนมือ 1 ใบ เพิ่มโควตาโจมตีในเทิร์นนั้น 1 ครั้ง ยังต้องจ่ายไพ่โจมตีและตรวจระยะ |
| เตรียมเสบียง | เริ่มช่วงจั่ว | สละการรับไพ่ช่วงจั่วทั้งหมด รวมสกิลแทนจั่ว เพื่อฟื้นฟู 1 HP |

มีช่องสนทนาผู้ชมแยกสำหรับผู้เล่นที่ตาย โดยเห็นเฉพาะข้อมูลสาธารณะ และดาวน์โหลดรายงาน JSON หลังจบแมตช์ได้ **ระบบคำมั่นถูกถอดออกแล้ว** ดูรายละเอียดใน [เอกสารแผนกลยุทธ์](docs/experimental-gameplay.md)

<a id="development"></a>
## พัฒนา

| ส่วน | เทคโนโลยีและตำแหน่ง |
| --- | --- |
| Client ปัจจุบัน | TypeScript, Vite 8, Three.js, GSAP, HTML/CSS ใน `client/` |
| กติกาและ protocol ร่วม | `shared/catalog.ts`, `shared/protocol.ts`, `shared/experimental.ts` |
| Server | TypeScript, Colyseus 0.15, Express ใน `colyseus_server.ts` และ `rooms/WTKRoom.ts` |
| ตรรกะเกม | เทิร์น การ์ด การต่อสู้ สกิล และบอท ใน `game/` |
| ข้อมูลถาวร | SQLite ผ่าน `db/database.ts`; สร้างตารางเมื่อเริ่ม Server |
| งานภาพ | Atlas ใน `public/art/`, texture สร้างครั้งเดียวใน `client/src/scene-textures.ts` |
| ผลลัพธ์ build | Server ใน `dist/`, Client ใน `public/pixel/` |
| Client เดิม | HTML/JS และ Phaser ใน `public/` สำหรับเส้นทาง legacy |

ใช้สอง terminal สำหรับพัฒนา UI พร้อม hot reload:

```bash
# Terminal 1: คอมไพล์ Server แล้วเปิดใช้งาน (PORT=3001 ใน .env)
npm run dev
```

```bash
# Terminal 2: Vite Client
npm run dev:client
```

เปิด **http://127.0.0.1:5173/pixel/** โดย Vite proxy `/api`, `/art`, `/fonts` และ Client WebSocket ในโหมด dev ชี้ไป Server ที่ `localhost:3001` หากแก้พอร์ตต้องปรับ `client/vite.config.mts` และ `client/src/connection.ts` ให้ตรงกัน `npm run dev` ไม่ใช่ Server watcher; เมื่อแก้ Server ต้องรันใหม่

### คำสั่ง

| คำสั่ง | หน้าที่ |
| --- | --- |
| `npm run build` | คอมไพล์ Server และสร้าง Client production |
| `npm run build:server` | คอมไพล์ Server อย่างเดียว |
| `npm run build:client` | สร้าง Client อย่างเดียว |
| `npm run check:client` | ตรวจชนิดข้อมูล Client โดยไม่เปิดเกม |
| `npm start` | เริ่ม Server จาก `dist/colyseus_server.js` |
| `npm test` | คอมไพล์ Server แล้วรัน Jest ใน `tests/` |
| `npm run verify:table` | สคริปต์ smoke check โต๊ะเกม ดูรายละเอียดในไฟล์ก่อนรัน |

คำสั่งทดสอบเป็นเครื่องมือสำหรับผู้พัฒนา ไม่ใช่ข้อกำหนดก่อนเปิดเล่น การผ่าน build/typecheck ไม่ได้ยืนยันว่ากติกา สมดุล หรือ layout ทุกอุปกรณ์ถูกต้องทั้งหมด

### การตั้งค่าและเส้นทาง

| ตัวแปร `.env` | ใช้งาน |
| --- | --- |
| `PORT` | พอร์ต HTTP/WebSocket; ตัวอย่างใช้ 3001 โค้ด fallback เป็น 3002 |
| `MONITOR_USER`, `MONITOR_PASS` | Basic Auth สำหรับ `/colyseus` |
| `ADMIN_SECRET_KEY` | รหัสสำหรับคำสั่ง admin |

| เส้นทาง | ใช้งาน |
| --- | --- |
| `/` | ส่งไป `/lobby` |
| `/lobby`, `/room`, `/app/:roomId`, `/room/:roomId` | Client รุ่นใหม่เมื่อมี `public/pixel/index.html` |
| `/api/rooms` | รายการห้องที่ยังไม่ล็อก |
| `/api/leaderboard` | อันดับผู้เล่นจากฐานข้อมูล |
| `/colyseus` | Monitor ที่ต้องยืนยันตัวตน |
| `/test` | ทางเข้า sandbox บอท |
| `/legacy/lobby`, `/legacy/room` | หน้า Client เดิม |

สำหรับ deployment ให้รัน `npm ci` และ `npm run build` ก่อน `npm start` เสิร์ฟ HTTP และ WebSocket ผ่าน origin เดียวกัน และใช้พื้นที่ถาวรสำหรับ `db/wtk_game.sqlite` หากต้องการเก็บสถิติข้ามการ deploy ไม่ควรนำ `.env`, ฐานข้อมูลจริง หรือ `node_modules/` ขึ้น Git

**ข้อจำกัด admin ปัจจุบัน:** Server ยังให้สิทธิ์ admin แก่ชื่อ `Admin` แบบไม่สนตัวพิมพ์ และมีทางเข้า sandbox การเปลี่ยน `ADMIN_SECRET_KEY` อย่างเดียวจึงยังไม่ปิดทางลัดเหล่านี้ ควรตรวจและจำกัดสิทธิ์ใน `rooms/WTKRoom.ts` ก่อนเปิด Server สาธารณะ
